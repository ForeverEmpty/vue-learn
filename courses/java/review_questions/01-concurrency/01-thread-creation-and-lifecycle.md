## 1. `Runnable task` 与 `Thread worker` 分别负责什么？只创建两者后，任务为什么还没有执行？

Runnable task负责创建一个任务对象
Thread worker负责创建一个线程对象
任务要调用run()或者交给线程对象，线程对象调用run()或start()来执行

Runnable 描述任务，Thread 承载执行并管理线程状态

> **批改：基本方向正确，但职责描述需要修正。** `Runnable task` 不是“负责创建任务对象”，它本身就是对“要做什么”的描述；`Thread worker` 也不是“负责创建线程对象”，它本身就是线程对象，保存线程名称、状态，并在启动后承载任务。只创建对象不会自动调用任务：显式调用 `run()` 会由当前线程执行，调用 `start()` 才会请求 JVM 启动新的执行路线。请按“描述任务 / 承载并管理执行”重新组织答案。

### 修正复核

已正确补充：`Runnable` 描述任务，`Thread` 承载执行并管理线程状态。结合原答案中必须显式调用 `run()` 或 `start()` 才会执行任务的说明，本题通过。

## 2. 直接调用 `worker.run()` 与调用 `worker.start()` 有什么本质区别？任务分别由哪个线程执行？

直接调用run()是在调用的线程执行，而start()是创建一个新的线程执行

> **批改：正确，补充一个用词细节。** `start()` 不会再创建一个新的 `Thread` Java 对象；`worker` 对象已经存在。它会请求 JVM 为这个对象启动新的执行路线，并由该工作线程执行 `run()`。直接调用 `run()` 则只是当前调用线程进行普通方法调用。

## 3. 为什么 `startAndWait` 必须先调用 `start()` 再调用 `join()`？如果只调用其中一个，会分别发生什么？

要先执行在等待执行完成
只调用start()主线程不会等待该线程完成后再执行
只调用join()不会启动该线程

> **批改：正确。** 更完整地说，只有 `start()` 才会让 worker 从 `NEW` 进入可运行阶段；`join()` 只负责让当前调用线程等待。只调用 `start()` 时 main 会立即继续；对尚未启动、并不存活的 worker 只调用 `join()` 时，等待会直接返回，任务不会执行。

## 4. 第一项测试为什么同时检查线程名称、`NEW` 状态和任务执行次数？这三个断言分别能发现哪类错误实现？

检查是否创建了正确的线程，线程有无执行和任务执行的几次

直接调用run()会执行任务，但worker状态可能仍保持NEW
NEW 状态断言能发现哪种提前启动错误；任务执行次数为 0 又能额外发现为什么 NEW 状态无法发现的错误

> **批改：方向正确，但三个断言还没有逐一对应到错误实现。** 请分别补充：线程名称断言能发现哪种参数使用错误；`NEW` 状态断言能发现哪种提前启动错误；任务执行次数为 `0` 又能额外发现为什么 `NEW` 状态无法发现的错误。提示：直接调用 `run()` 后，`Thread` 对象的状态仍可能是 `NEW`。

### 修正复核

已抓住 `run()` 执行任务却不改变线程启动状态这一关键边界，本题通过。三个断言的完整对应关系是：名称断言发现忽略或错误使用 `workerName`；`NEW` 状态发现提前调用 `start()`；执行次数为 `0` 还能发现直接调用 `run()` 这种状态断言无法识别的提前执行。
