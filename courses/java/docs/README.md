## 学习约定

- 正式章节按顺序推进。
- 遇到会阻碍当前内容的前置知识时，直接插入一章基础知识，再回到当前正式章节。
- 基础知识章只讲解和演示，不自动生成复习题；需要时由学习者主动提出。

## 后续正式章节的设计标准

- 常规章节安排约 4～6 个递进实现检查点，不再以修改一两个表达式作为整章主体。
- 推进顺序优先采用“建立基础行为 → 复现真实问题 → 引入新机制 → 处理边界条件 → 组合成完整场景”。
- 每章至少包含一项需要多个方法或对象协作的综合练习，并让测试结果随检查点逐步改善。
- 新章节要复用前章已经掌握的线程创建、等待、共享状态或同步关系，明确说明知识之间的依赖。
- 内容量以新增行为、边界和设计判断衡量，不为增加代码行数而加入无关样板。

## 后续路线

1. `wait`、`notifyAll` 与线程协作：逐步实现一个有容量限制、可阻塞等待的生产者—消费者缓冲区。
2. `volatile` 与 Java 内存模型的可见性。
3. `Lock`、`Condition` 和原子类。
4. 线程池、`ExecutorService`、`Future` 与 `CompletableFuture`。
5. 并发集合与常见并发设计。

章节会根据理解难度调整检查点和复习题数量，不固定每章题数。
