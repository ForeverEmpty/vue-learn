# Java 模块 02：反射、注解元数据与动态代理

本模块是并发模块之后的下一条 Java 高级主线。目标不是记忆 `java.lang.reflect` API，而是理解 Java 程序怎样在运行时观察类型、根据元数据创建对象，并在不修改目标类的情况下拦截方法调用。

模块尚未开启正式的 `02·01`，当前文件只定义递进路线；开始学习时再创建对应源码、验收和复习题。

## 最终综合项目

整个模块会逐步构建一个纯 Java 的迷你对象容器：

```text
一组候选 Class
    ↓ 读取运行时注解
组件定义
    ↓ 选择构造器并解析依赖
对象实例
    ↓ 必要时创建动态代理
可调用的组件 + 日志/计时拦截
```

它不是复制 Spring，而是用较小规模理解框架常用的底层机制：运行时元数据、对象工厂、依赖图、代理与异常边界。

## 递进章节

### 02·01：运行时类型与 `Class<?>`

- 比较 `obj.getClass()`、`Type.class` 与 `Class.forName(...)`。
- 识别普通类、接口、数组、枚举、record 和基本类型的运行时信息。
- 区分“获得类信息”与“触发类初始化”。
- 建立类型目录，按类名查找已注册类型。

综合产物：一个显式注册、可查询且能拒绝重复类型的 `TypeRegistry`。

### 02·02：构造器、字段与方法

- 使用 `Constructor`、`Field`、`Method` 读取成员信息。
- 理解 public、declared、继承成员和访问边界的差异。
- 根据参数类型选择构造器并创建实例。
- 正确翻译反射调用产生的检查异常与目标方法异常。

综合产物：一个只允许明确构造规则、错误信息稳定的 `ObjectFactory`。

### 02·03：运行时注解与元数据驱动

- 复用 Java 00·09 的注解与元注解知识。
- 理解 `@Retention(RUNTIME)`、`@Target` 和注解默认值。
- 为组件和构造器声明课程专用注解。
- 把原始反射对象转换成稳定的组件定义，不让反射细节泄漏到业务代码。

综合产物：从候选类型中提取 `ComponentDefinition` 的元数据读取器。

### 02·04：动态代理与调用链

- 使用 `Proxy` 与 `InvocationHandler` 代理接口。
- 正确处理参数、返回值、`Object` 方法和目标异常。
- 组合日志、计时等多个拦截行为。
- 区分代理模式的设计意图与 JDK 动态代理的实现限制。

综合产物：可以为接口组件添加日志与计时能力的代理工厂。

### 02·05：迷你对象容器

- 根据构造器参数建立依赖关系。
- 按依赖顺序创建和缓存单例对象。
- 识别缺失依赖、重复组件和循环依赖。
- 在对象创建完成后按规则应用动态代理。
- 用一个小型命令处理场景验证容器，而不是只打印反射信息。

综合产物：组合前四章能力的 `MiniContainer`，并形成可运行的完整调用链。

## 模块边界

- 初期只处理显式传入的候选类，不一开始实现复杂的 classpath 扫描。
- 不通过反射任意破坏私有封装；需要开放访问时会说明适用边界和模块系统限制。
- 不把所有异常统一吞掉或包装成无信息的 `RuntimeException`。
- 不在第一章一次塞入容器、注解和代理；每一章只引入当前可观察行为所需的机制。
- 如果出现 `Class<?>`、泛型边界、检查异常或类加载等前置障碍，会在 Java `00-foundation` 中单开对应基础章节。

## 章节内容量约定

- 每章约 4～6 个实现检查点。
- 单个检查点通常修改一个聚焦行为，完整章节需要多个类或方法协作。
- 自动验收只反馈行为；复习题可混合机制解释、代码审查、调试和约 10～40 行核心代码的编程题。
- 最终代码必须服务于迷你对象容器，不用无关样板人为增加代码量。
