# Java 基础 00·15：正则表达式

正则表达式（regular expression，常写作 regex）是一种描述**字符串格式**的语言。它不是 Java 独有语法：Java、JavaScript、数据库和命令行工具都支持正则，但具体功能和转义规则可能略有差异。

当前 Spring Boot 章节需要限制主题的 `slug`：只能使用小写字母、数字和单个短横线，例如 `spring-boot`。本章从这个真实规则出发，建立阅读和编写基础正则所需的完整思路。

本章属于按需查询的基础知识，不设置复习题。

## 1. 正则解决什么问题

如果只校验一个固定字符串，可以直接比较：

```java
boolean valid = input.equals("spring-boot");
```

但当我们想表达“一整类合法字符串”时，逐个枚举就不现实了。例如：

```text
spring
spring-boot
http2-basics
java-21
```

它们都满足同一种格式：

```regex
[a-z0-9]+(?:-[a-z0-9]+)*
```

正则适合描述：

- 字符是否来自允许的集合；
- 某一部分出现几次；
- 字符串以什么开头或结尾；
- 多种格式中任选一种；
- 从文本中查找符合格式的片段。

正则不适合代替业务逻辑。例如“slug 是否已被其他主题使用”需要查询应用状态，不能只看字符串格式。

## 2. 先区分普通字符和元字符

大多数字母和数字表示它们自己：

```regex
java
```

它只描述连续出现的 `j`、`a`、`v`、`a`。

有些符号在正则中具有特殊含义，称为元字符：

```text
.  ^  $  *  +  ?  {  }  [  ]  (  )  |  \
```

例如 `.` 通常表示任意字符，并不是普通句点。要匹配真正的句点，需要写成：

```regex
\.
```

看到正则时，不要尝试一次读完整行。应按“字符集合 → 次数 → 组合关系 → 边界”的顺序拆开。

## 3. 字符类：当前位置允许什么字符

方括号 `[]` 表示当前位置可以从一组字符中选择一个。

| 写法 | 含义 | 可匹配的一个字符示例 |
| --- | --- | --- |
| `[abc]` | `a`、`b`、`c` 中任意一个 | `b` |
| `[a-z]` | 任意小写英文字母 | `m` |
| `[A-Z]` | 任意大写英文字母 | `Q` |
| `[0-9]` | 任意一位数字 | `7` |
| `[a-z0-9]` | 小写字母或数字 | `g`、`4` |
| `[^0-9]` | 除数字以外的一个字符 | `x`、`-` |

需要特别注意：

```regex
[a-z0-9]
```

只匹配**一个**字符。它并不自动表示一整个单词。匹配多少次由后面的量词决定。

一些常用简写如下：

| 简写 | 常见含义 | 近似展开 |
| --- | --- | --- |
| `\d` | 数字 | `[0-9]` |
| `\s` | 空白字符 | 空格、制表符、换行等 |
| `\w` | 单词字符 | 字母、数字、下划线；具体 Unicode 行为需结合选项确认 |

当业务规则要求非常明确时，直接写 `[a-z0-9]` 往往比 `\w` 更清楚，因为 `\w` 还允许下划线，而且大小写范围不如显式规则直观。

## 4. 量词：前一部分允许出现几次

量词控制它前面的一个字符、字符类或分组出现的次数。

| 量词 | 含义 | 示例 |
| --- | --- | --- |
| `?` | 0 次或 1 次 | `colou?r` 可匹配 `color`、`colour` |
| `*` | 0 次或多次 | `[0-9]*` 也允许空串 |
| `+` | 1 次或多次 | `[0-9]+` 至少有一位数字 |
| `{3}` | 恰好 3 次 | `[0-9]{3}` |
| `{2,5}` | 2 到 5 次 | `[a-z]{2,5}` |
| `{2,}` | 至少 2 次 | `[a-z]{2,}` |

比较下面两条规则：

```regex
[a-z0-9]*
[a-z0-9]+
```

第一条允许出现 0 次，因此空字符串也能匹配；第二条要求至少出现一次。slug 不能为空，所以本章使用 `+`。

## 5. 分组与选择

圆括号把多个部分组合为一个整体，竖线 `|` 表示“或者”。

```regex
(java|spring)
```

它可以匹配 `java` 或 `spring`。

普通圆括号还会记录匹配内容，称为**捕获组**。如果只是为了组合结构，不需要稍后读取内容，可以使用非捕获组：

```regex
(?:java|spring)
```

两者对“是否匹配”的结果相同；`(?:...)` 只是明确表示该组仅用于组织规则。

量词会作用于紧挨着它的整个分组：

```regex
(?:-[a-z0-9]+)*
```

这里的 `*` 控制的不是某一个字符，而是整个“一个短横线，后面跟至少一个字母或数字”的片段。

## 6. 边界：匹配整串还是局部

两个常见锚点是：

```text
^  字符串开头
$  字符串结尾
```

下面的正则明确要求整串都是数字：

```regex
^[0-9]+$
```

如果使用 Java `Matcher.matches()` 或 Bean Validation 的 `@Pattern`，规则本身就按整个字符串匹配，因此经常可以省略 `^` 和 `$`：

```regex
[0-9]+
```

但使用 `Matcher.find()` 时，程序是在更长文本中寻找任意符合规则的片段。此时是否需要锚点取决于你的目标。

## 7. 逐段读懂本章的 slug 正则

完整规则是：

```regex
[a-z0-9]+(?:-[a-z0-9]+)*
```

先拆为两部分：

```text
[a-z0-9]+          第一段
(?:-[a-z0-9]+)*    后续段
```

第一段 `[a-z0-9]+` 表示：

1. 只能是小写字母或数字；
2. 至少出现一次。

后续段 `(?:-[a-z0-9]+)*` 表示：

1. 先出现一个短横线；
2. 短横线后必须有至少一个小写字母或数字；
3. 整个片段可以出现 0 次或多次。

因此它的结构可以写成：

```text
字母数字段 (-字母数字段) (-字母数字段) ...
```

逐个判断示例：

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `spring` | 接受 | 只有第一段，后续段出现 0 次 |
| `spring-boot` | 接受 | 第一段后有一个完整的 `-boot` |
| `http2-basics` | 接受 | 数字属于 `[a-z0-9]` |
| `Spring-Boot` | 拒绝 | 字符类没有包含大写字母 |
| `-spring` | 拒绝 | 第一段必须先出现，不能以短横线开头 |
| `spring-` | 拒绝 | 短横线后缺少 `[a-z0-9]+` |
| `spring--boot` | 拒绝 | 每个短横线后必须立刻进入非空字母数字段 |
| `spring boot` | 拒绝 | 规则没有允许空格 |

这里没有单独编写“禁止连续短横线”的规则。通过定义合法结构，连续短横线自然无法匹配。这通常比不断罗列非法情况更容易维护。

## 8. Java 字符串还有一层转义

正则和 Java 字符串是两层不同的语法。

如果正则本身需要：

```regex
\d+
```

Java 字符串中反斜线也有特殊含义，所以需要再转义一次：

```java
String regex = "\\d+";
```

可以按下面的顺序理解：

```text
Java 源码 "\\d+"
        ↓ Java 解析字符串
正则引擎看到 \d+
        ↓ 正则解析
含义：一位或多位数字
```

本章 slug 规则没有反斜线，因此 Java 注解里可以直接写：

```java
@Pattern(regexp = "[a-z0-9]+(?:-[a-z0-9]+)*")
```

再看一个匹配 Windows 风格反斜线的例子。正则层面需要 `\\` 表示一个普通反斜线，而 Java 字符串还要再次转义：

```java
String regex = "\\\\";
```

当正则没有按预期工作时，先确认问题发生在“Java 字符串转义”还是“正则含义”，不要把两层语法混在一起猜。

## 9. Java 中的 `Pattern` 与 `Matcher`

`Pattern` 表示已经编译的正则规则，`Matcher` 负责把规则应用到具体字符串。

```java
import java.util.regex.Pattern;

public class SlugExample {
    private static final Pattern SLUG_PATTERN =
            Pattern.compile("[a-z0-9]+(?:-[a-z0-9]+)*");

    public static boolean isValidSlug(String value) {
        return value != null && SLUG_PATTERN.matcher(value).matches();
    }

    public static void main(String[] args) {
        System.out.println(isValidSlug("spring-boot"));  // true
        System.out.println(isValidSlug("Spring Boot")); // false
    }
}
```

反复使用同一个规则时，把 `Pattern` 保存为 `static final`，不必每次都重新编译。

`Matcher` 的三个常见方法不能混淆：

| 方法 | 含义 | 示例：规则 `[0-9]+`，输入 `id=42` |
| --- | --- | --- |
| `matches()` | 整个输入都要符合 | `false` |
| `find()` | 输入中存在符合的片段即可 | `true`，找到 `42` |
| `lookingAt()` | 从输入开头开始符合即可，不要求到结尾 | `false` |

Java 还提供简写：

```java
boolean valid = "spring-boot".matches("[a-z0-9]+(?:-[a-z0-9]+)*");
```

它适合一次性的小判断；规则会频繁执行时，预先编译的 `Pattern` 意图更清楚，开销也更可控。

## 10. `@Pattern` 在 Spring 请求校验中的位置

Bean Validation 可以把正则直接声明在请求 DTO 上：

```java
public record CreateTopicRequest(
        @Pattern(
                regexp = "[a-z0-9]+(?:-[a-z0-9]+)*",
                message = "slug must use lowercase letters, numbers, and single hyphens"
        )
        String slug
) {
}
```

`@Pattern` 只负责格式。它通常需要和 `@NotBlank` 配合：

```java
@NotBlank(message = "slug is required")
@Pattern(...)
String slug
```

两者职责不同：

```text
@NotBlank  负责“必须提供有内容的字符串”
@Pattern   负责“提供的字符串必须符合指定结构”
```

Spring Controller 参数上的 `@Valid` 才会触发这些约束。完整职责关系可回到 Spring 基础 00·14 查看。

## 11. 编写正则的可靠步骤

面对新规则时，可以遵循以下顺序：

1. 先列出几组应接受和应拒绝的真实输入。
2. 把字符串拆成稳定的结构片段，不急着写元字符。
3. 为每个片段确定允许的字符类。
4. 为每个片段确定出现次数。
5. 需要整体重复时再加分组。
6. 明确程序要匹配整串还是查找局部。
7. 最后处理 Java 字符串的额外转义。

以 slug 为例：

```text
结构草图：字母数字段 (-字母数字段)*
字符集合：[a-z0-9]
非空段：[a-z0-9]+
重复后缀：(?:-[a-z0-9]+)*
组合结果：[a-z0-9]+(?:-[a-z0-9]+)*
```

这种“从数据结构翻译成规则”的方式，比从一长串符号反推含义更稳定。

## 12. 常见误区

- 把 `.` 当普通句点，意外接受任意字符。
- 忘记 `*` 允许出现 0 次，导致空串也被接受。
- 使用 `[a-z0-9]` 后忘记量词，只匹配一个字符。
- 把 `[a-z-0-9]` 之类不清晰的短横线位置写进字符类；短横线可能被解释为范围，最好放在开头、结尾或进行转义。
- 在 Java 中写 `"\d+"`；这是非法或错误的 Java 转义，正则 `\d+` 应写成 Java 字符串 `"\\d+"`。
- 需要整串校验却使用 `find()`，只要局部合法就误判为通过。
- 用正则承担需要查询数据库、集合或其他服务的业务规则。
- 为了“一条正则解决所有问题”写出难以解释的超长表达式；清晰的普通代码有时更合适。

还要避免对外部输入使用结构复杂、重复层层嵌套的正则，例如随意组合 `(.*)+`。某些表达式在不匹配的长输入上会产生大量回溯，造成明显性能问题。当前 slug 规则由明确字符类和简单重复组成，不需要宽泛的 `.*`。

## 13. 快速查询表

| 语法 | 含义 |
| --- | --- |
| `[abc]` | 从 `a`、`b`、`c` 中匹配一个 |
| `[a-z]` | 一个小写英文字母 |
| `[^a-z]` | 一个非小写英文字母 |
| `.` | 通常表示任意字符 |
| `\.` | 普通句点 |
| `X?` | `X` 出现 0 或 1 次 |
| `X*` | `X` 出现 0 或多次 |
| `X+` | `X` 出现 1 或多次 |
| `X{2,4}` | `X` 出现 2 到 4 次 |
| `(X)` | 捕获分组 |
| `(?:X)` | 非捕获分组 |
| `X|Y` | `X` 或 `Y` |
| `^`、`$` | 输入开头、输入结尾 |
| `\\d`（Java 字符串） | 正则引擎最终看到 `\d` |

## 阅读完成标准

读完后，只需能够：

- 把 `[a-z0-9]+(?:-[a-z0-9]+)*` 拆成两个结构片段并解释每个量词；
- 判断它为什么拒绝开头、结尾或连续短横线；
- 区分 `matches()` 的整串匹配和 `find()` 的局部查找；
- 知道正则反斜线进入 Java 字符串时通常需要再次转义；
- 知道格式规则属于正则，资源是否重复属于业务状态。
