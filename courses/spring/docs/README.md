## 章节设计约定

- 每个常规章节安排约 4～6 个递进检查点。
- 推进顺序优先采用“建立基础行为 → 交给框架管理 → 暴露外部接口 → 处理失败边界 → 完整集成验证”。
- 理论直接放在需要它的正式章节中，并指出它解释了哪段可观察行为。
- 正式章节首次出现新的 Spring 注解、核心类型、重要注解属性、设计思想或设计模式时，在 `00-foundation/` 单开小章，并从使用位置建立反向链接。
- 正式章节保留足以理解当前代码的上下文；详细定义、放置位置、运行机制、适用边界和常见误区放进对应 00 基础小章。
- 设计思想或模式仍各自单开详细小章，并尽量提供可运行示例；只是统一归入一个 00 模块，避免出现两个不同的 00 目录。
- 遇到 Java 语言前置知识时，在 Java `00-foundation` 新建独立小章，再返回当前检查点；基础小章不自动生成复习题。
- 测试只作为自动验收工具；除非学习者主动提出，正式章节和复习题不要求掌握测试框架、测试分类、测试注解或断言 API。
